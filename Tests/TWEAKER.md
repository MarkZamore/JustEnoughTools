# Проверка твикера

## Автоматические проверки

`TweakTests` использует подставные `ITweakBackend`, `ITweakPlatform`, файловую систему и прогресс. Набор не вызывает реальные setters Windows, PowerShell расшифровки, рекурсивную обработку C: или обычный entrypoint экспортированного EXE.

Проверяются:

- независимое выполнение поддействий и продолжение после ошибки;
- пропуск применённых, неизвестных, неподтверждённых и недоступных состояний;
- отказ от setter неподтверждённого адаптера и неожиданного типа реестра;
- локальное выполнение пользовательских действий, один административный пакет и отмена UAC;
- закрытый набор идентификаторов IPC, ограничения размера, отсутствие повторов и проверка ответов;
- один успешный поиск Windows Update за сеанс и сохранение управляющих политик;
- сохранение семейства состояния и времени отключения классической автозагрузки;
- сохранение атрибутов файлов, пропуск ошибок и reparse points, закрытие прогресса и фиксация признака корня последним;
- отказ от фиксации корня при отмене и проверка завершения BitLocker по состоянию, а не округлённому проценту.

UI-проверка подставляет весь сервис. Она проверяет 13 строк, порядок слева направо, две равные колонки, разделитель, независимость кнопки заголовка, её выравнивание с «Сохранить», одинаковую вертикальную ось названий, компактные промежутки и отсутствие любых статусов у строк. Короткие причины блокировки относятся к кнопкам, общие пояснения — к названиям; у доступных кнопок подсказки нет. Проверяются разные состояния и занятость приложения. Окно не показывается и стартовые production-проверки не запускаются; отрисовка выполняется вне экрана при нескольких размерах и DPI.

## Лабораторные границы

Обычные реальные изменения при разработке выполняются только в отдельной лабораторной Windows VM. Для перечисленной ниже дополнительной проверки пользователь отдельно разрешил кратковременное переключение оставшихся настроек Пуска, панели задач и процента батареи на основной Windows с возвратом исходных значений. Это исключение не распространяется на защиту, дисковые операции или другие твики. Внутренние параметры разрешает встроенный перечень сочетаний сборки и конкретного параметра. Он не является пользовательской настройкой и не загружается из sidecar-файла. Проверка записи и чтения не заменяет сопоставление с реальным переключателем Windows.

На других сборках или при недоступном состоянии соответствующие поддействия остаются заблокированными. Отсутствие значения не считается отсутствием функции; известный стандартный вариант учитывается отдельно. Неподтверждённые значения, защищённые записи реестра Widgets, политики и неизвестные форматы автозагрузки не изменяются.

Проверка C: при запуске намеренно ограничена признаком корня и свойством BitLocker оболочки. Она не подтверждает состояние каждого вложенного файла. Сохранённые настройки оболочки могут потребовать следующего входа или перезагрузки; программа их не инициирует. Системные кэши темы, журналы и работа службы BitLocker/Windows Update не являются собственными файлами настроек приложения.

Диски, ISO, учётные данные, личные пути, сырые трассы и служебные сценарии лаборатории в репозиторий не включаются. Результаты лабораторных прогонов относятся только к указанной в перечне сборке и поднастройкам; они не доказывают поведение всех будущих выпусков Windows.

## Подтверждённые механизмы и ограничения

В изолированной Windows 11 Pro проверены сборки 26300.9457 и 26300.9711. Перечень разрешённых параметров хранится в `TweakCompatibility`; он различается по сборкам.

- На 26300.9457 сопоставлены стандартное, противоположное и целевое состояния переключателей истории буфера, недавно добавленных приложений, рекомендаций, уведомлений учётной записи, папок Пуска, поиска, представления задач, emoji, пера, сенсорной клавиатуры, часов центра уведомлений и параметров Windows Update. Прежнее предположение о параметре видимости даты и времени отозвано: запись старого ключа не подтверждает изменение переключателя.
- На 26300.9711 повторно сопоставлены целевые состояния перечисленных настроек Пуска и папок, поиска, представления задач, emoji, пера, сенсорной клавиатуры и часов; подтверждено левое выравнивание значков. Тихое применение полной темы и нативные настройки клавиатуры, курсора, залипания и мыши выполнены в интерактивном пользовательском сеансе с последующим чтением состояния.
- На 26300.9711 проверены классическая тестовая запись автозагрузки и существующая пакетная запись: состояние отключения, сохранность команды и `UserEnabledStartupOnce`, тип времени отключения. Дополнительно открыт настоящий раздел автозагрузки диспетчера задач. Неизвестные форматы не изменяются.
- На 26300.9711 дополнительно проверены противоположное и целевое состояния истории буфера и всех пяти предпочтений Windows Update. Для панели задач подтверждены положение снизу, размер по умолчанию, эмблемы, мигание, режим отображения приложений на дисплеях, оба режима объединения кнопок, предоставление доступа к окнам, показ рабочего стола и уменьшение значков при переполнении. Для положения, размера и уменьшения значков также проверено отсутствие значения: стандартные варианты совпадают с целевыми.
- Найдены и проверены в обе стороны действующие параметры Resume и видимости даты/времени; прежние неработающие кандидаты заменены. Показ секунд проверен через раскрытый настоящий переключатель Windows, без изменения часового пояса, форматов или запуска синхронизации.
- Для обоих дополнительных часов проверены включённое, выключенное и стандартное состояния в настоящем диалоге Windows. Из-за ограниченного UIA-провайдера состояние двух обнаруженных нативных флажков прочитано через `BM_GETCHECK`; отсутствие UIA-паттерна не использовалось как доказательство выключения. Отключение не меняет сохранённые подписи и часовые пояса дополнительных часов.
- Выполнен полный рекурсивный проход индексирования C: в VM: обработано 46 556 объектов, пропущено 227 567. Признак корня установлен после завершения; защищённые файлы, включая проверенный образец, сохранены без изменения ACL. Диалог закрывается после завершения. Отмена и сохранение прочих атрибутов дополнительно проверены на подставной файловой системе.
- На реально зашифрованном C: с ожидающей активацией BitLocker сопоставлены свойство оболочки `8`, фактическое состояние `FullyEncrypted` и 100% шифрования. Выполнен встроенный сценарий расшифровки: получены `FullyDecrypted`, 0% шифрования и свойство оболочки `2`. Интерпретация состояния `8` разрешена только для проверенной сборки; пустые и неизвестные значения по-прежнему не означают отсутствие шифрования.
- Настоящий EXE запущен в VM без повышения. «Применить все» сначала включило историю буфера исходного пользователя, затем один запрос UAC обслужил административные изменения Windows Update и классической автозагрузки. Подтверждены сохранность команды автозагрузки, состояние отключения, целевое предпочтение Update и завершение единственного рабочего процесса. Последующий поиск Windows Update успешно завершился без установки обновлений.

Весь путь UAC с другим административным пользователем и настройки оборудования с батареей в этой лаборатории не проверены. Протокол повышения, отмена и разделение пользовательского контекста дополнительно проверены автоматическими тестами с подставными адаптерами. Реальный пакет UAC проверен с подтверждением повышения тем же пользователем.

## Дополнительная проверка на основной Windows

На сборке 26300.9711 с новым интерфейсом Пуска, батареей и несколькими дисплеями выполнена отдельно разрешённая пользователем проверка. Это подтверждение на основной ОС, а не результат лабораторной VM.

- Для секций закреплённого, недавнего и всех приложений сопоставлены выключенное значение `0`, включённое `1` и исходное отсутствие параметра при включённой секции. Подтверждено каноническое имя `ShowAllAppsSection`.
- Автоматический размер Пуска соответствует `StartMenuSize=0`, маленький — `1`; исходное отсутствие значения соответствует автоматическому размеру. Для скрытия имени/аватара сопоставлено включение `HideUserInformation=1`, исходное отсутствие значения и выключенный переключатель.
- Для виртуальной сенсорной панели сопоставлены `TouchpadDesiredVisibility=1/0` и исходное отсутствие значения при выключенном переключателе. Для меню скрытых значков сопоставлены `SystemTrayChevronVisibility=1/0`.
- Для панели на всех дисплеях сопоставлены `MMTaskbarEnabled=1/0` и исходное отсутствие значения при включённом флажке. Для оптимизации планшета сопоставлены `ExpandableTaskbar=1/0`. Неизвестные стандартные значения последнего параметра и меню скрытых значков по-прежнему не угадываются.
- Эти девять поднастроек разрешены только на 26300.9711. Значения по умолчанию добавлены только там, где проверено исходное отсутствие записи.
- Первоначальный кандидат процента батареи не подтвердился: запись `IsBatteryPercentageEnabled` и `TraySettings` не изменили видимую панель. Дополнительная проверка секунд выявила ту же проблему. Пользователь подтвердил отсутствие эффекта как после вызова старого адаптера, так и после запуска настоящего автономного EXE Autonomy&Performance только с процентом батареи.
- После проверки восстановлены исходные состояния всех десяти затронутых записей: семь отсутствующих значений удалены, три существовавших значения DWORD возвращены; результат перечитан. Переключатели возвращены в исходные положения. Обход защиты, изменение ACL, перезапуск Explorer, установка обновлений и применение других твиков не выполнялись.

Прямая запись защищённого предпочтения Widgets исключена; в выпуске 16 включён проверенный брокер, описанный ниже. Составные строки применяют только подтверждённые доступные поднастройки; короткая подсказка сообщает о пропусках. На сборках вне перечня внутренние параметры остаются недоступными.

## Брокер процента батареи и секунд

На основной Windows 26300.9711 отдельно проверены оба направления двух настроек через `SystemSettings.DataModel.SettingsBroker` → пользовательскую `GetSettingsDatabase` → фиксированные `SystemSettings_PowerAndBattery_BatteryPercentageToggle` и `SystemSettings_DesktopTaskbar_SecondsInSystrayClock`. Интерфейсы и порядок методов сопоставлены с установленным `SystemSettings.DataModel.winmd`; значение — строго Boolean `Value`.

Прямое создание обработчика из SettingsHandlers DLL изменяло читаемое им предпочтение, но не видимую панель. Брокер изменил настоящие переключатели Windows; пользователь визуально подтвердил исчезновение и процента, и секунд на панели задач. После проверки оба значения возвращены во включённое состояние и перечитаны через брокер; исходные DWORD реестра также восстановлены. Этот результат относится к основной ОС, а не к VM.

Общий исходник адаптера одинаков в JustEnoughTools и Autonomy&Performance. Он не открывает Settings, не вызывает UI/action `Invoke`, не меняет права, не выбирает другую учётную запись и не использует реестр как запасной способ. Проверяются применимость, возможность изменения, политика и незавершённая операция. После собственного setter выполняется ограниченная проверка результата; фонового опроса нет. Ошибка или отсутствие интерфейса остаются неизвестным/недоступным состоянием и не вызывают UAC. Автоматические тесты используют подставной backend; реальное чтение проверено в STA и MTA.

Нативные объекты целиком создаются и освобождаются в MTA внутри того же процесса. Первое чтение ограниченно ожидает готовность модели; запись подтверждается устойчивым значением в нескольких новых сессиях брокера. Оптимистичное значение объекта, выполнившего запись, подтверждением не считается.

В собранном JustEnoughTools 15 выполнены выключение процента батареи и секунд и последующее независимое чтение. Затем настоящий автономный EXE, созданный Autonomy&Performance 30 с единственным действием процента батареи, включил его, сохранив секунды выключенными; код A&P отдельно включил секунды. Все операции подтверждены новыми моделями; исходные включённые состояния возвращены. Это отдельно разрешённая реальная проверка на основной ОС, не автоматический тест CI.

## Аудит похожих предпочтений

В обоих проектах сопоставлены текущие состояния 30 похожих настроек. Найдено дополнительное расхождение меню пера: старый параметр отсутствует, но `SystemSettings_DesktopTaskbar_InkWorkspace` возвращает включённое состояние, соответствующее интерфейсу Windows. Меню пера переведено на тот же брокер; аппаратно зависимое стандартное значение не угадывается.

Новый адаптер меню пера разрешён только на 26300.9711. Прежняя проверка реестрового способа на 26300.9457 не переносится на него автоматически.

Остальные сопоставленные текущие состояния истории буфера, секций Пуска, рекомендаций, задач, эмблем, мигания, нескольких дисплеев, предоставления доступа к окнам, показа рабочего стола, оптимизации планшета, виртуальной сенсорной панели, даты и часов совпали. Это проверка чтения текущего состояния, а не доказательство немедленного эффекта каждого setter. Для сохраняемых предпочтений результат по-прежнему явно отложенный.

Индексы списков брокера отличаются от чисел старого реестра: их нельзя подставлять без проверки идентичности вариантов. Параметр `SystemSettings_DesktopTaskbar_Recommended` описан как видимость предложений и не подтверждён как значок Resume; им не заменяется проверенный адаптер Resume. В Autonomy&Performance дополнительно воспроизведён ошибочный успех старого ночного света и проверен работающий цветовой тёмный режим; результаты и исправление описаны в его документации.

## Расширение брокера, выпуск 16

Общий закрытый каталог и типизированный WinRT-адаптер одинаковы в обоих проектах. Boolean, UInt32, Int32 и строки списков проверяются до записи. Строковые варианты выбираются из `PossibleValues`, без жёсткого задания переведённой подписи. Индексы оболочки сопоставлены отдельно: они отличаются от прежних чисел реестра. На неподтверждённых сборках новые внутренние сопоставления не включаются автоматически.

На отдельно разрешённой основной Windows 26300.9711 выполнены противоположное значение и возврат для 43 доступных переключателей/списков Пуска и панели задач, включая девять независимых папок, Widgets, процент батареи и секунды. Два параметра нескольких дисплеев были неприменимы и пропущены. Кандидат `DesktopTaskbar_Sh` после проверки системного поискового ресурса оказался настройкой поиска при наведении, поэтому исключён. `DesktopTaskbar_Autohide` неприменим; автоскрытие сохраняет проверенный SHAppBarMessage. Политики и `IsEnabled`/`IsApplicable`/`IsUpdating` проверяются у каждого поддействия. Дополнительных окон Settings, UI action Invoke и перезапуска Explorer нет.

Сохраняются нативные адресные механизмы, для которых безопасный эквивалент брокера не подтверждён: полная тема с фоном (тихий COM), мерцание курсора, два дополнительных часовых пояса, автоскрытие панели задач, дисковые операции, перечни классической/пакетной автозагрузки и поиск обновлений. Поиск выполняет Windows Update API без установки. Повторное выполнение совпадающих значений не требуется. Залипание сочетает независимые переключатели брокера с проверенным SPI для скрытых флагов, недоступных при выключенной основной функции.

Пользовательские предпочтения Windows Update применяются в исходном процессе до определения необходимости единственного административного пакета. Регистрация Microsoft Update остаётся отдельно проверяемой административной операцией только при подтверждённой необходимости; отмена UAC не отменяет пользовательские изменения.

В интерактивном сеансе отдельной Pro VM 26300.9711 новые переключатели буфера, задержки/скорости клавиатуры, ускорения мыши, залипания, Resume и пяти предпочтений Windows Update переключены в обе стороны с возвратом. Скрытые четыре переключателя залипания проверены отдельно при временно включённой основной функции. Клавиатура и отключённое ускорение дополнительно прочитаны через SPI; скорость указателя сохранена. Первоначальный запуск без интерактивного сеанса дал отказы и не считался подтверждением; после восстановления сеанса прогоны завершились без ошибок. Исходные лабораторные предпочтения, временные параметры входа и тестовое задание возвращаются после проверки. Реальные изменения Windows Update на основной ОС не выполнялись.

Ранее подтверждённые legacy-механизмы 26300.9457 сохранены отдельно от новых broker-сопоставлений: не выполняется слепой fallback после ошибки брокера или политики. Документированные SPI клавиатуры/мыши/залипания доступны и на сборках без новой сертификации. При старом HKLM-пути Windows Update административная область не теряется. Финальная фаза поиска не повторяет уже предпринятые пользовательские записи.

# JustEnoughTools

- Пользовательское приложение: Windows 11 x64, .NET Framework 4.8, один EXE. Все managed-зависимости и ресурсы встроены и загружаются из памяти.
- Обычная работа не сохраняет настройки приложения в файлах или реестре и не распаковывает зависимости. Разрешённые файловые исключения: скрытый `JustEnoughTools.update` рядом с EXE; явно сохранённый пользователем автономный EXE и один временный файл рядом с его целью; выбранные пользователем ярлыки меню «Пуск» и обслуживание собственных ярлыков. Не добавлять `.bak`, sidecar JSON, журналы или файловый helper. Не заявлять отсутствие системных кэшей и журналов Windows.
- Стиль задаётся `Source/Theme.xaml` по Autonomy&Performance. Стартовый и минимальный размер 820×560 DIP; сохранять системную рамку, Snap и размеры текста. Пустые WalkieTalkie и Clicker не содержат действий.
- Номер выпуска равен числу коммитов в `main`. До коммита собирать корневой EXE с номером будущего коммита, обновлять changelog и включать EXE в тот же коммит. CI публикует отслеживаемые байты, а не собственную повторную сборку.
- Видимые в Windows FileVersion и ProductVersion основного и экспортированного EXE — одно число N без префикса 1.0 и суффикса .0. В обоих проектах FileVersion=$(ReleaseNumber), InformationalVersion=$(ReleaseNumber); внутренний Version=1.0.N и техническая AssemblyVersion=1.0.N.0 сохраняются и не используются как видимая версия.
- После изменения выполнить `Source/Build.ps1 -ReleaseNumber N`, `Tests/Test.ps1 -ExecutablePath JustEnoughTools.exe`, `.github/tests/ReleaseTests.ps1`. После изменений установки обновления проверить disposable-process integration suites.
- Настройка защиты использует фиксированный перечень документированных действий без открытия Settings/Windows Security/браузера; UAC и один итоговый диалог только при проблемах допустимы. Исключены шифрование, действия с перезагрузкой, обход Tamper Protection, изменение ACL/владельцев, удаление или остановка защищённых компонентов. Проверять каждое действие независимо; запись предпочтения не подменяет подтверждение эффективного состояния. Старых профилей и диагностических CLI быть не должно.
- Основной и экспортированный EXE запускаются как asInvoker. Сначала выполнять проверку без изменений; запрашивать UAC только при подтверждённой необходимости доступных административных действий. Неизвестное состояние не считать выключенным и не использовать как единственную причину повышения прав. В интерфейсе проверять при запуске и после собственной операции, без постоянного опроса; если все доступные действия уже выполнены, «Отключить» недоступна.
- RTP проверяется по фактическому состоянию; AlwaysPrompt/NeverSend уже удовлетворяют отсутствию автоматической отправки образцов. Условные политики изменяются только при существующем явном значении и подтверждённой применимости; отсутствие политики не доказывает включённое состояние. Tamper Protection, Smart App Control, SmartScreen Store и отмену текущего сканирования не программировать без отдельного подтверждённого способа проверки/применения; возвращать причины пропуска.
- Все реальные изменения защиты и экспериментальные проверки выполнять только в отдельной лабораторной VM. Основную Windows и CI при разработке не изменять. В автоматических основных тестах использовать подставные системные адаптеры; не запускать обычный entrypoint экспортированного EXE. Не считать отсутствие интерфейса, ошибку доступа или остановленную службу доказательством отключения.
- Лабораторные диски, ISO, учётные данные, личные пути и исходные трассы не публиковать. В итогах чётко различать подтверждённые проверки и непроверенные возможности.
- Исправление панели задач работает только с HKCU/MMTaskbarMode и уведомлением текущего Explorer без UAC; его тесты используют подставной backend. Экспорт содержит фиксированное действие Security/TaskbarMode1/TaskbarMode2 в проверенном ресурсе PE без sidecar; отсутствие или повреждение действия должно завершать исполнение до любых изменений.

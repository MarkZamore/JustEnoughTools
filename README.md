# JustEnoughTools

Портативное приложение Windows 11 x64: один `JustEnoughTools.exe` на системном .NET Framework 4.8. Установка современного .NET пользователю не нужна.

[Скачать EXE](https://github.com/MarkZamore/JustEnoughTools/releases/latest/download/JustEnoughTools.exe) · [Выпуски](https://github.com/MarkZamore/JustEnoughTools/releases/tag/latest)

Палитра, шрифты, отступы и элементы интерфейса следуют Autonomy&Performance. WalkieTalkie и Clicker пока являются пустыми раскрывающимися категориями.

## Отключить защиту Windows (временно)

Кнопки «Отключить», «Сохранить» и квадратная кнопка выбора иконки находятся в строке заголовка. Чекбокс «Добавить в меню пуск» расположен ниже, под значком настройки слева. Описание о правах администратора показывается только при известных действиях, которым они нужны.

«Отключить» выполняет фиксированный перечень доступных штатных действий. Интерфейс работает с обычными правами и сначала проверяет состояние без изменений. Только при известных доступных административных действиях отдельный экземпляр того же EXE запрашивает UAC. Если всё доступное уже отключено, кнопка недоступна и повторного применения нет. Проверка выполняется при запуске и после собственной операции, без постоянного опроса. Неизвестное состояние не считается выключенным и само по себе не вызывает повышение прав. «Параметры», Windows Security, браузер и консоль во время выполнения не открываются.

| Область | Действия |
|---|---|
| Defender | Защита в реальном времени, облачная защита, автоматическая отправка образцов, блокировка PUA, контролируемый доступ к папкам. Существующие исключения и списки папок/приложений сохраняются. |
| Плановое сканирование | Отключение только штатной задачи Windows Defender Scheduled Scan при доступных правах. |
| Брандмауэр | Отдельное отключение доменного, частного и общедоступного профилей. Службы Firewall/BFE не останавливаются. |
| Условные политики | SmartScreen Windows, SmartScreen и блокировка нежелательных загрузок Edge, усиленная защита от фишинга, скрытие антивирусного раздела Windows Security — только при подтверждённой применимости и существующем явном значении политики, требующем изменения. |

Применимость и результат проверяются отдельно для каждого действия. Отказ Defender не блокирует доступное изменение брандмауэра. Результат различает подтверждённое изменение, уже заданное значение, блокировку, отсутствие поддерживаемого способа и неподтверждённое состояние. Одной записи значения в реестр недостаточно для подтверждения эффективного отключения. Для Firewall также учитывается результирующая политика.

Уже выключенные функции повторно не настраиваются. Для защиты в реальном времени учитывается фактический статус: выключенное RTP не требует записи предпочтения. Для отправки образцов режимы AlwaysPrompt и NeverSend уже означают отсутствие автоматической отправки; AlwaysPrompt сохраняется.

Для PUA принимаются два состояния без блокировки: Disabled (`0`) и Audit (`2`). Уже установленный Audit сохраняется: обнаружение и события аудита остаются, но PUA не блокируются. Это не полное отключение обнаружения. В лаборатории Windows возвращала значение `2` после установки `0`; приложение не пытается постоянно перезаписывать его. [Описание режимов PUA Microsoft](https://learn.microsoft.com/en-us/defender-endpoint/detect-block-potentially-unwanted-apps-microsoft-defender-antivirus).

На Home корпоративная политика не считается автоматически поддерживаемой. Отсутствующее или неизвестное значение политики не доказывает, что соответствующий переключатель интерфейса включён; новая политика в таком случае не создаётся. Применимость редакции, сборки и управления устройством проверяется отдельно; запись поддерживаемой политики не выдаётся за подтверждение её эффективного действия.

Tamper Protection, Smart App Control и SmartScreen приложений Store программно не изменяются. Отмена текущего быстрого или полного сканирования также пропускается: в проекте не подтверждён надёжный документированный способ сначала определить активное сканирование без изменений. Для этих пунктов возвращается причина, а не успех. Шифрование и действия, требующие перезагрузки ОС, исключены. Разделы учётных записей, семьи и работоспособности устройства не являются общими выключателями защиты.

Если все доступные действия уже выполнены и неизвестных состояний нет, повторного применения и дополнительного окна нет. При отказах, частичном или неподтверждённом выполнении показывается один итоговый диалог. Статуса под карточкой нет. «Временно» означает отсутствие гарантии постоянного отключения, а не автоматический откат при закрытии программы: настройки могут сохраняться после перезагрузки, Windows или управляющая политика могут позднее вернуть значения. Фоновый процесс повторного отключения не устанавливается.

Обход самозащиты, изменение владельцев или ACL, массовые исключения, удаление системных файлов, защищённых служб и драйверов не используются. Скрытие раздела интерфейса не считается отключением антивирусного движка. Функция не обещает постоянного отсутствия всех источников сканирования или карантина.

Документация Microsoft: [предпочтения Defender](https://learn.microsoft.com/en-us/powershell/module/defender/set-mppreference?view=windowsserver2025-ps), [API брандмауэра](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nf-netfw-inetfwpolicy2-put_firewallenabled), [SmartScreen](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-smartscreen).

## Сохранение автономного EXE

После настройки защиты расположено «Исправление панели задач», перенесённое из Autonomy&Performance. Двухпозиционный тумблер выбирает режим 1 (главная панель и панель экрана с окном) либо режим 2 (панель экрана с окном); нейтрального положения нет. «Применить» выполняет исправление для текущего пользователя без запроса UAC и без перезапуска Explorer. При незавершённой последовательности восстанавливается исходный параметр. Подсказка сохраняет полные названия режимов.

У каждой карточки свои «Сохранить», выбор иконки и чекбокс меню «Пуск». В плиточном меню две встроенные иконки — защита и панель задач — и выбор своего ICO. Сохранённое «Исправление панели задач.exe» выполняет только выбранный режим; действие встроено в ресурсы EXE, отдельного файла конфигурации нет.

«Сохранить» создаёт `Отключить защиту Windows.exe` либо файл с выбранным именем. Он содержит предварительно собранный RunnerTemplate и тот же модуль действий, запускается с обычными правами и проверяет состояние без изменений. При известных доступных административных действиях он повышает права отдельного экземпляра себя и выполняет настройку, без открытия конструктора. Если всё доступное уже отключено, повторного применения и UAC нет. Ресурсы не распаковываются, компиляция при сохранении не запускается.

Доступны две тематические встроенные иконки или пользовательский ICO. Кадры всех разрешений встраиваются в EXE. При недоступности выбранного ICO используется встроенная иконка. Сохранение использует один временный файл рядом с целью: полная запись и проверка, затем замена без backup. Ошибка замены сохраняет существующий исправный EXE.

Чекбокс «Добавить в меню пуск» включён по умолчанию и относится только к сохранению. Он создаёт собственный ярлык текущего пользователя в папке меню «Пуск» JustEnoughTools. Повторное сохранение обновляет собственную ссылку и иконку, не перезаписывая чужие ярлыки. При следующем запуске конструктора фоновое обслуживание пытается восстановить пути собственных ярлыков после перемещения файлов и безопасно обрабатывает устаревшие ссылки; недоступность диска или незавершённый поиск не доказывают удаление EXE. Постоянного наблюдателя нет.

## Портативность и обновления

Приложение не сохраняет собственные настройки в файлах или реестре. XAML, иконки и managed-зависимости встроены и загружаются из памяти. Явные файловые исключения: сохранённый пользователем EXE, один временный файл его сохранения, выбранные ярлыки с обслуживанием собственных ссылок и скрытый `JustEnoughTools.update` рядом с основным EXE. Собственные журналы, sidecar JSON, резервные EXE и файловый helper не создаются. Системные журналы и кэши Windows/PowerShell учитываются отдельно.

При запуске проверяется GitHub release `latest`. Полный EXE либо подходящая прямая дельта загружаются и проверяются в памяти по размеру и SHA-256; при ошибке дельты используется полный файл. Готовое обновление сохраняется одним скрытым пакетом. «Обновить» устанавливает его с повторным запуском; обычное закрытие — без повторного открытия окна. Незавершённая подготовка отменяется.

Замена выполняется системным PowerShell командой в памяти и `MoveFileExW`, без скрипта на диске, backup и `~RF*.TMP`. При ошибке замены исправная копия сохраняется; гарантированный откат без backup невозможен. Обновление согласовано с выполняемой настройкой через mutex.

## Сборка и проверка

Для сборки нужны Windows, .NET SDK 10.0.400 или совместимый 10.0 SDK и NuGet при первом восстановлении. Номер выпуска равен числу коммитов в `main`; перед следующим коммитом используется текущее число плюс один. Начиная с выпуска 5 видимые в Windows версия файла (FileVersion) и версия продукта (ProductVersion) показывают одно число `N`, как в Autonomy&Performance. Внутренняя AssemblyVersion сохраняет технический формат `1.0.N.0`.

```powershell
.\Source\Build.ps1 -ReleaseNumber 7
.\Tests\Test.ps1 -ExecutablePath .\JustEnoughTools.exe
.\.github\tests\ReleaseTests.ps1
```

`--self-test` проверяет встроенные зависимости без изменения защиты. Обычные автоматические тесты и CI не запускают системные setters и обычный entrypoint экспортированного EXE. Все реальные изменения защиты проверяются только в отдельной VM; основная Windows не изменяется. Подтверждённые сценарии и границы наблюдения описаны в [Tests/PORTABILITY.md](Tests/PORTABILITY.md).

Сборка 5 завершилась без ошибок и предупреждений; локально прошли 385 проверок приложения, 26 проверок выпуска и 9 проверок происхождения исходников. Проверены видимые строки FileVersion=`5` и ProductVersion=`5`, техническая AssemblyVersion=`1.0.5.0`. В выпуске изменены метаданные версии; защитная логика не менялась и повторным изменениям в VM для нового SHA-256 не подвергалась.

Реальные VM-наблюдения относятся к выпуску 4 с хешем `2957794C…9BD6BA5F`: запуск на Home/Pro без современного .NET, экспорт Runner, отсутствие повторного UAC при уже заданных значениях и уже повышенном интерфейсе. На Pro RTP осталось включённым при Tamper Protection; на Home Windows включила RTP обратно после перезагрузки даже при выключенной Tamper Protection. Остальные проверенные значения сохранились. [GitHub Actions выпуска 4](https://github.com/MarkZamore/JustEnoughTools/actions/runs/39485170353) завершился успешно; опубликованные полный EXE, манифест schema 2 и прямые дельты 2→4 и 3→4 проверены, включая контрольное восстановление целевого EXE из обеих баз. Полное или постоянное отключение всей защиты не заявляется; точные хеши и границы проверки приведены в отчёте.

GitHub Actions проверяет исходники, номер и отпечаток корневого EXE и публикует именно отслеживаемые байты. Полный EXE, `update.json` schema 2 и до двух прямых дельт публикуются без дополнительных коммитов CI. Исходники, changelog и готовый корневой EXE включаются в один коммит. VM, трассы и учётные данные не публикуются.

Сторонние зависимости перечислены в `THIRD-PARTY-NOTICES.txt`, также встроенном в EXE.

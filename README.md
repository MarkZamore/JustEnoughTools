# JustEnoughTools

Портативное приложение Windows 11 x64. Один `JustEnoughTools.exe`, системный .NET Framework 4.8; установка .NET 10 пользователю не нужна.

[Скачать JustEnoughTools.exe](https://github.com/MarkZamore/JustEnoughTools/releases/latest/download/JustEnoughTools.exe) · [Описание выпуска](https://github.com/MarkZamore/JustEnoughTools/releases/tag/latest)

Интерфейс использует палитру, шрифты и отступы Autonomy&Performance. Окно открывается в размере 820 × 560 DIP и сохраняет системную рамку, Windows Snap и масштабирование DPI. WalkieTalkie и Clicker пока являются пустыми раскрывающимися категориями.

## Текущее состояние

Интерфейс, встроенные зависимости, проверка обновлений и выпуск полных/дельта-пакетов реализованы. Кнопка «Отключить» проверяет возможность штатного отключения Defender и скрытия его раздела в Windows Security.

**В этом выпуске нет проверенного профиля применения политик. Приложение проверяет условия и сообщает причину отказа; настройки защиты и интерфейса не меняются.** Для Home возвращается «Не поддерживается», для неподтверждённых конфигураций Pro/Enterprise/Education — «Не подтверждено». Это диагностический выпуск, а не универсальный выключатель антивируса.

Проверяются редакция/сборка Windows, версия платформы и состояние Defender, Tamper Protection, Smart App Control, подключение к Defender for Endpoint и сведения Windows Security Center. Недоступные сведения остаются неизвестными и не считаются выключенным состоянием. Эти данные остаются локально; запросы обновления не отправляют собранный снимок в GitHub.

## Ограничения штатной настройки

Документированные политики отключения и скрытия раздела не заявляют поддержку Home. Политика отключения в Pro/Enterprise/Education зависит от Tamper Protection и управления устройством; Microsoft также предупреждает о возможном неподдерживаемом поведении legacy-настройки. Сохранённый DWORD, остановленная служба или исчезнувшее окно не считаются подтверждением отключения. Источники: [политика отключения](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-microsoftdefenderantivirus#disableantispywaredefender), [ограничения DisableAntiSpyware](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/security-malware-windows-defender-disableantispyware).

Политика [DisableVirusUI](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-windowsdefendersecuritycenter#disablevirusui) скрывает раздел защиты от вирусов, а не удаляет Windows Security. В проекте предусмотрены отдельные подтверждения неактивности движка, скрытия раздела и устойчивости настройки после перезагрузки/обновления политики. Неполные и неподтверждённые результаты не превращаются в успех. Обход Tamper Protection, изменение защищённых служб, удаление системных файлов, подмена регистрации антивируса и фоновый процесс подавления защиты не используются.

Даже штатное автоматическое отключение при другом зарегистрированном антивирусе зависит от его состояния, MDE и Smart App Control. Оно не гарантирует, что Defender никогда не включится после изменения конфигурации. [Матрица совместимости Microsoft](https://learn.microsoft.com/en-us/defender-endpoint/microsoft-defender-antivirus-compatibility).

## Портативность

Приложение не сохраняет собственные настройки, не распаковывает DLL и не создаёт собственных каталогов. Ресурсы и managed-зависимости находятся внутри EXE и загружаются из памяти.

Единственное собственное файловое исключение — скрытый `JustEnoughTools.update` рядом с EXE, когда скачано обновление. При включённом показе скрытых файлов этот пакет виден. Системные события, кэши и журналы Windows/PowerShell относятся к операционной системе и не подавляются.

Первый выпуск проверен на чистой Windows 11 Home 26H2 x64, сборка 26300.9457, с системным .NET Framework и без установленного современного .NET. Единственный EXE успешно выполнил проверку встроенных зависимостей и оба диагностических запроса. Проверка настройки вернула Unsupported без изменений; Defender остался активным. При проверенном открытии и закрытии интерфейса папка приложения не изменилась; системная трасса при этом содержит записи Windows в реестр и метаданные системных DLL. Абсолютное отсутствие следов не заявляется. Фактические сценарии и границы проверки описаны в [Tests/PORTABILITY.md](Tests/PORTABILITY.md).

## Обновления

При запуске программа проверяет release `latest` в GitHub и автоматически готовит новую версию. Дельта выбирается по номеру версии и фактической SHA-256 текущего EXE; при отсутствии подходящего патча или ошибке его применения скачивается полный файл. Размеры и SHA-256 проверяются до установки.

Кнопка «Обновить» закрывает программу, устанавливает обновление и запускает новую версию. Обычное закрытие устанавливает готовое обновление без повторного открытия окна. Незавершённые загрузки хранятся в памяти и при закрытии отменяются. После штатной установки скрытый пакет исчезает.

Замена выполняется штатным Windows PowerShell командой в памяти, без файла скрипта, журнала и резервного EXE. После аварии пакет проверяется следующим запуском. Единственная исправная копия при ошибке замены не удаляется. Автоматический откат без резервного файла не гарантируется.

В выпусках 1–2 применялся `File.Replace`: реальный прогон выявил создаваемые Windows промежуточные имена `~RF*.TMP`. В выпуске 3 используется `MoveFileExW` для замены в том же каталоге, без копирования и удаления старого EXE отдельной командой. P/Invoke объявляется в памяти через Reflection.Emit; компилятор `Add-Type` не вызывается. При обновлении версии 1 или 2 установку ещё выполняет старый helper, поэтому это исправление действует для последующих обновлений из версии 3. Полный EXE версии 3 можно скачать напрямую.

На GitHub публикуются полный EXE, `update.json` schema 2 и до двух прямых bsdiff-патчей. Первый выпуск не имеет предыдущей базы; две дельты доступны начиная с третьего успешного выпуска.

## Сборка и проверки

Нужны Windows, .NET SDK 10.0.400 или совместимый установленный 10.0 SDK и доступ к NuGet при первом восстановлении зависимостей.

```powershell
.\Source\Build.ps1 -ReleaseNumber 1
.\Tests\Test.ps1 -ExecutablePath .\JustEnoughTools.exe
.\.github\tests\ReleaseTests.ps1
```

`JustEnoughTools.exe --inspect-protection`, `--inspect-configuration` и `--check-configuration` доступны для локальной диагностики через перенаправленный стандартный вывод. Они не запрашивают повышение прав и не меняют настройки.

Номер выпуска равен количеству коммитов в `main`. Перед следующим коммитом собрать EXE с номером `git rev-list --count HEAD` плюс один, обновить `Source/Changelog.md` и включить исходники с корневым EXE в один коммит. Для первого коммита используется номер 1.

GitHub Actions проверяет исходники и публикует точные байты отслеживаемого корневого EXE; дополнительных коммитов CI не создаёт. Встроенный отпечаток исходников позволяет выявить устаревший EXE даже при совпадающем номере версии. Подробные записи лабораторных испытаний и VM не входят в репозиторий.

Сведения о сторонних библиотеках находятся в `THIRD-PARTY-NOTICES.txt` и встроены в EXE.

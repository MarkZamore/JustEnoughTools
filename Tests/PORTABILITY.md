# Проверка портативности

`PortabilityTests` и `ConfigurationCommandTests` автоматически входят в общий
запуск `Tests/Test.ps1`. Они работают с EXE, переданным через
`TestContext.ExecutablePath`, а не с соседними DLL сборочной папки. Проверяются:

- заголовки PE и архитектуру AMD64;
- встроенный Win32 manifest: обычный запуск `asInvoker`, `uiAccess=false`,
  масштабирование `PerMonitorV2`;
- запуск копии единственного EXE через `--self-test` без DLL, `.config` и
  установленного рядом runtime;
- отсутствие изменений в папке этой копии во время проверки зависимостей.

`ConfigurationCommandTests` дополнительно запускает байтовую копию того же
EXE через `--inspect-configuration` и `--check-configuration`. Процессы
запускаются напрямую с `UseShellExecute=false`; тест не вызывает `runas` и не
инициирует повышение прав. Проверяется непустой JSON, наличие источников и
пояснений у наблюдений, сохранение неизвестных значений как `null`, типы
логических значений и допустимые диапазоны enum. Для текущего выпуска без
проверенных профилей результат проверки обязан иметь `Succeeded=false`,
`CanApply=false`, `PerformedChanges=false`, остальные признаки изменения и
подтверждения также `false`, а статус — Unsupported, Blocked либо Unverified.
Пояснение должно быть содержательным, а не прежней заглушкой удаления. При
известной редакции Home/Core проверяется Unsupported с указанием редакции.

Каждый набор создаёт собственную временную папку в игнорируемом
`Tests/Artifacts/Portability`, копирует в неё только EXE и наблюдает за ней через
`FileSystemWatcher`. Ошибка/переполнение наблюдателя считается провалом. Для
`--self-test` EXE дополнительно открыт только для чтения без разрешения записи
и удаления. После завершения проверяются неизменность байтов и состав папки,
затем удаляется только созданная тестом папка с уникальным именем.

Среда дочернего процесса не содержит `DEVPATH`, `APP_CONFIG_FILE` и
`COMPLUS_Version`; `PATH` содержит только системный каталог Windows,
`DOTNET_ROOT` указывает на отсутствующий путь, а
`DOTNET_MULTILEVEL_LOOKUP=0`. Эти изменения касаются только дочернего процесса.
Они исключают случайную зависимость от CLI из `PATH`, но не заменяют проверку
на гостевой системе без .NET 10.

## Аудит исходников

Проект приложения задаёт `net48`, `x64` и встраивает XAML, иконку, changelog,
уведомления о лицензиях и managed-зависимости в ресурсы EXE.
`DependencyBootstrap` разрешает зависимости из ресурсов и вызывает
`Assembly.Load(byte[])`; распаковки DLL на диск в этом пути нет.
`--self-test` действительно создаёт и применяет BsDiff-патч в памяти, поэтому
проверяет работу обеих встроенных библиотек BsDiff и SharpZipLib.

`Source/Tools` и `Source/Patch` содержат инструменты сборки, которые записывают
файлы, но исключены из компиляции приложения. Создание готового пакета,
удаление повреждённого пакета и установка обновления находятся в
`Source/Updates`; для них нужны отдельные сценарии обновления. Этот набор не
запускает установку обновления и не изменяет защиту Windows.

## Подтверждённый результат

20 октября 2026 года общий прогон `Tests/Test.ps1` завершился успешно:
`PASS total: 385`, включая `ConfigurationCommandTests: 8` и
`PortabilityTests: 12`. Проверенный EXE имел версию `1.0.1.0`, размер
920064 байта и SHA-256:

```text
76E46DDFC884EB7549E08C11E2E741C0186821735DD7A2C64629FE9E64D21917
```

Байты запускаемых копий EXE сохранились. Наблюдатели не зарегистрировали
изменений внутри их папок; после запуска в каждой находился только неизменённый
`JustEnoughTools.exe`. После последующих изменений EXE результат относится к
новым байтам только после повторного прогона набора.

Отдельно в чистой Windows 11 Home/Core 26H2 x64, сборка 26300.9457, проверен
именно выпуск 1 с указанным выше SHA-256: системный .NET Framework имеет
Release=533509, стандартные каталоги современных .NET runtime отсутствуют.
`--self-test` и диагностические CLI завершились с кодом 0; Home возвращает
Unsupported без применения изменений. Оператор запустил единственный EXE через
Explorer, дождался сообщения о последней версии (1), раскрыл обе пустые
категории, получил объяснение неподдерживаемой Home без UAC и закрыл окно
кнопкой X. Procmon XML подтвердил Explorer как родителя, Integrity=Medium,
64-битный процесс без виртуализации и штатный выход с кодом 0. Независимая
проверка после закрытия обнаружила только неизменённый EXE, без скрытого пакета;
Defender оставался в Normal, Antivirus/RealTimeProtection/TamperProtection — true.

Гостевая трасса Procmon 4.12 длилась около 82 секунд: потоково разобраны 903042
CSV-записи, включая 17301 событие процесса приложения; потомков не обнаружено.
Изменений в каталоге приложения не найдено, но успешные операции из его PID
существуют: 140 `RegSetInfoKey` с `KeySetHandleTagsInformation`, 12 `SetEAFile`
на системных .NET/WPF DLL и 34 создания/записи ключей и значений Windows Tracing
(`JustEnoughTools_RASAPI32`, `JustEnoughTools_RASMANCS`), ZoneMap, CTF,
Notifications и BAM. Это не собственные настройки приложения; классификация
по системным путям не доказывает отсутствие следов Windows/runtime и не
означает нулевые записи в реестр. Отдельно выделены 56 операций кандидатов
системных кэшей других процессов и 15 операций наблюдателя. EULA, драйвер,
PML/CSV/XML и файлы harness относятся к наблюдателю вне каталога приложения.
Счётчик потерь/переполнений не доступен в этих CSV/XML, поэтому абсолютная
полнота kernel capture и отсутствие любых иных следов не заявляются.

## Границы результата

- На машине проверки установлены .NET 10 и системный .NET Framework. Запуск на
  чистой Windows подтверждён отдельно указанным выше гостевым сценарием;
  один только основной машинный прогон этого не доказывает.
- Эти наборы проверяют `--self-test` и два диагностических CLI. Они не открывают
  основной интерфейс, не применяют настройки, не проверяют все пути обычной
  работы и не скачивают обновления.
- Наблюдение только за папкой копии не доказывает отсутствие записей в других
  местах файловой системы или в реестре. Это также не полный аудит всех
  транзитивных действий библиотек и Windows.
- На основной Windows системная трассировка не запускалась. Гостевая трасса
  относится только к описанному GUI-сценарию. Она не подтверждает абсолютное
  отсутствие файловых и реестровых следов: положительные системные операции
  перечислены выше, журналы и кэши Windows учитываются отдельно.

Лабораторный сценарий Procmon и анализатор его CSV подготовлены отдельно от
репозитория. Анализатор проверен на синтетических событиях и применён к
сохранённой гостевой трассе. Её первоначальный полный CSV превысил безопасный
лимит памяти гостевого анализатора; затем CSV корректно прочитан потоковым
парсером с учётом кавычек и многострочных полей. Все события приложения и его
потомков сохранены в выборке; исходные PML/CSV/XML оставлены приватными.

Скачивание и установка обновления требуют отдельного гостевого прогона с
единственным разрешённым собственным файлом `JustEnoughTools.update`; они не
входили в эту обычную GUI-трассу. Чтения, открытие существующих ключей и
неуспешные попытки записи не считаются созданными артефактами. Проверка других
сборок, всех путей сетевых ошибок и реальных переходов между мониторами с
разными DPI остаётся отдельной работой.

Исходные трассы, образы VM, диски, учётные данные и личные пути в репозиторий не
добавляются. Итоговая запись о проверке должна содержать только обезличенные
сценарии, хеш EXE, версию ОС, фактические результаты и ограничения наблюдения.

# Проверка портативности текущего приложения

## Контракт текущей реализации

Основное приложение и экспортируемый Runner — Windows x64 EXE на .NET Framework 4.8. XAML, иконки, RunnerTemplate и managed-зависимости основного приложения встроены; при обычной работе DLL и конфигурации на диск не распаковываются. Оба EXE имеют manifest `asInvoker`: сначала выполняется проверка без изменений, повышение прав запрашивается отдельным экземпляром только при известных доступных административных действиях.

Разрешённые собственные файловые операции:

- один скрытый `JustEnoughTools.update` рядом с основным EXE для готового обновления;
- EXE, явно выбранный пользователем при сохранении, и один соседний временный файл для проверенной замены;
- выбранные ярлыки меню «Пуск» и обслуживание собственных отмеченных ссылок.

Собственных настроек приложения в реестре, sidecar JSON, журналов, backup и файлового helper нет. Изменения системных параметров защиты — явный результат нажатия «Отключить» либо запуска сохранённого EXE. Системные журналы и кэши Windows, Shell, .NET и PowerShell не подавляются и не считаются настройками приложения.

## Автоматические проверки

`Tests/Test.ps1` работает с переданным отслеживаемым EXE. Проверяются AMD64 PE, manifest, встроенные ресурсы и запуск байтовой копии единственного EXE через безопасный `--self-test` без соседних DLL, `.config` или современного runtime. Этот режим создаёт и применяет BsDiff-патч в памяти.

Тестовые копии располагаются в игнорируемом `Tests/Artifacts`. FileSystemWatcher проверяет замеченные имена и изменения; переполнение или ошибка наблюдателя считается провалом. Неизменность байтов и состав каталога проверяются после завершения. Наблюдение каталога не доказывает отсутствие системных записей в других местах.

Тесты нового модуля настройки используют подставные системные адаптеры. На основной Windows и в CI не выполняются системные setters, не запускается обычный entrypoint сохранённого Runner и не меняются настройки защиты. Проверки экспорта работают с тестовыми целями и ярлыками, без обслуживания реального пользовательского меню «Пуск».

Для новой реализации отдельно проверяются частичные результаты, отказ доступа, отсутствие API, повторный и параллельный запуск, расхождение сохранённого и эффективного значения, ошибки ICO, безопасная замена и сохранение исправной цели при блокировке. Проверка состояния без изменений должна отличать известные ожидающие действия от неизвестного результата; при уже заданных значениях не нужны setters или UAC. В интерфейсе кнопка недоступна, если всё доступное уже отключено; постоянного опроса нет. Реальные UAC, системные политики и поведение после перезагрузки требуют VM.

Проверка текущего модуля отдельно сохраняет следующие границы: фактическое RTP Off уже удовлетворяет настройке независимо от предпочтения; отправка образцов AlwaysPrompt и NeverSend не требует повторного отключения автоматической отправки. Для условных SmartScreen/Edge/Phishing/VirusUI-политик отсутствие явного значения не доказывает включённое состояние и не разрешает создавать новую политику. Изменяются только известные существующие значения на поддерживаемой конфигурации, а результат не подменяет подтверждение эффективного поведения.

Для PUA значения Disabled (`0`) и Audit (`2`) считаются отсутствием блокировки. Audit сохраняет обнаружение и события; он не объявляется полным отключением сканирования. [Microsoft описывает Audit как обнаружение без блокировки](https://learn.microsoft.com/en-us/defender-endpoint/detect-block-potentially-unwanted-apps-microsoft-defender-antivirus).

Tamper Protection, Smart App Control и SmartScreen Store программно не переключаются. Отмена текущего сканирования помечается недоступной: надёжная документированная проверка активного быстрого или полного сканирования без изменений не подтверждена, вызова отмены нет. Эти пропуски должны сохранять содержательную причину в результате.

## Запуск и результаты

Исправление панели задач использует только HKCU/MMTaskbarMode и уведомление Explorer. Переход «Все панели» → «Панель задач, в которой открыто окно», откат при ошибке и встроенное действие экспортированного EXE проверяются подставным backend; ресурс дополнительно читается штатным Windows API без запуска entrypoint. Проверки не применяют режим к реальным панелям основной Windows.

Состав действующих проверок и команды запуска — в [README.md](README.md). Исторические VM-прогоны и хеши предыдущих EXE вынесены в [архив](../docs/verification-history.md).
